НОВАЯ РЕАЛЬНОСТЬ — ТЕСТОВАЯ ВЕРСИЯ CRM 2.1

Это отдельная тестовая копия исходного сайта. Она не связана с опубликованным Netlify-проектом spiffy-kheer-42015a и не должна развёртываться поверх него.

ОСНОВНЫЕ СТРАНИЦЫ
- index.html — главная
- catalog.html — каталог
- configurator.html — 3D-конструктор
- business-center.html — корзина и отправка заявки в тестовую CRM
- account.html — регистрация/вход клиента, история его заявок
- manager.html — защищённый вход сотрудника, рабочее место менеджера и администратора
- contacts.html — контакты
- kvass.html — «Русский Квас»
- tour.html — виртуальная экскурсия

CRM-КОМПОНЕНТЫ
- auth.js — общий клиент Supabase Auth
- account.js — кабинет клиента
- manager.js / manager.css — рабочее место сотрудников
- business-center.js — корзина и отправка заказов
- netlify/functions/public-config.mjs — выдаёт браузеру только публичные параметры Supabase
- netlify/functions/admin-users.mjs — серверные административные операции с учётными записями сотрудников
- supabase/migrations/202611090001_crm_core.sql — таблицы, функции и правила доступа к данным
- SETUP-TEST-CRM.md — полная инструкция по настройке тестовой базы и первого администратора

ВАЖНО
Перед запуском нужно создать отдельный TEST-проект Supabase, применить SQL-миграцию, скопировать .env.example в .env и заполнить тестовые ключи. Не используйте ключи production.

ЗАПУСК
В терминале из папки проекта:
  npm install
  npm install -g netlify-cli
  netlify dev

Откройте локальный URL, который сообщит Netlify CLI (обычно http://localhost:8888). Live Server и открытие HTML через file:// не подходят для проверки CRM, потому что проект использует Netlify Functions.

БЕЗОПАСНОСТЬ
- .env уже исключён из Git и не должен попадать в ZIP.
- SUPABASE_SECRET_KEY / SUPABASE_SERVICE_ROLE_KEY используется только Netlify Functions; браузеру передаётся только SUPABASE_PUBLISHABLE_KEY / SUPABASE_ANON_KEY.
- Регистрация на сайте всегда создаёт роль customer. Самостоятельно назначить себе manager/admin нельзя.
- Менеджер получает заявки только с assigned_to = его собственный ID. Проверка доступа выполняется в Supabase RPC, а не только в интерфейсе.
- Клиент видит только заявки, привязанные к его аккаунту.
- Администратор назначает заявки и управляет менеджерами.

ОГРАНИЧЕНИЯ ПЕРВОЙ CRM-ВЕРСИИ
Сами файлы-вложения пока не загружаются; в CRM сохраняются только их метаданные. Гостевые заявки не связываются с аккаунтом задним числом. Перед запуском на реальных клиентах нужны антиспам-защита, проверка политики персональных данных, SMTP и резервное копирование.

Не выполнять netlify link/deploy с рабочим сайтом spiffy-kheer-42015a. Для будущего удалённого тестирования создаётся отдельный Netlify-проект.
